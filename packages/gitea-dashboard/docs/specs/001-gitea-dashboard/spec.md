# Feature Specification: Gitea Dashboard — расширение браузера для репозиториев, PR и сборок

**Feature Branch**: `001-gitea-dashboard`

**Created**: 2026-09-26

**Status**: Draft

## Clarifications

### Session 2026-09-26

- Q: Что считать «нашими репами» для сборок и «Остальных открытых» PR? → A: все репозитории организаций, где состоит разработчик (+ свои), закреплённые сверху, с исключениями; запасной режим — по репозиториям с лимитом 30.
- Q: Что по умолчанию показывает раздел «Сборки» при охвате всех организаций? → A: две группы — «Мои и закреплённые» развёрнута, «Остальные» свёрнута со счётчиком активных и упавших.
- Q: Внешний вид и язык (после первой сборки владелец счёл UI «уродским»)? → A: React + канонический shadcn/ui без кастомизации (без border-border), интерфейс всегда на русском.
- Q: Как команда ставит и обновляет расширение? → A: архив с версией в релизах Gitea, собирается CI по тегу; установка «загрузить распакованное» по README; обновление вручную.

**Input**: User description: "Chrome-расширение «Gitea Dashboard»: быстрый переход к репозиториям нашего self-hosted Gitea, открытые Pull Requests (моё ревью / мои / остальные) со статусом CI, мониторинг сборок Gitea Actions, бейдж на иконке, фоновый опрос, системные уведомления, страница настроек, горячие клавиши и переход из адресной строки. ## User Scenarios & Testing *(mandatory)*

Действующее лицо одно — **разработчик**, у которого есть учётная запись в нашем Gitea и личный токен доступа. Расширение работает от его имени и видит ровно то, что видит он сам.

### User Story 1 — Подключение к Gitea (Priority: P1)

Разработчик ставит расширение, указывает адрес Gitea и личный токен, нажимает «Проверить подключение» и получает понятный ответ: всё работает, или что именно не так (адрес недоступен, токен неверный, токену не хватает прав, сборки на этой версии Gitea недоступны).

**Why this priority**: без подключения не работает ни одна другая функция; это вход в продукт.

**Independent Test**: установить расширение на чистый профиль браузера, ввести адрес и токен, проверить сообщение диагностики для верного токена, неверного токена, неверного адреса и токена с урезанными правами.

**Acceptance Scenarios**:

1. **Given** расширение только что установлено, **When** разработчик открывает окно расширения, **Then** видит приглашение открыть настройки, а не пустой экран или ошибку.
2. **Given** верный адрес и токен, **When** разработчик нажимает «Проверить подключение», **Then** видит имя своей учётной записи, версию Gitea и отметку, что сборки доступны.
3. **Given** неверный токен, **When** проверка, **Then** сообщение «токен недействителен» и ссылка на страницу создания токена в Gitea.
4. **Given** токен без части прав, **When** проверка, **Then** сообщение называет, какой функции не хватает прав и какое право добавить; остальные функции продолжают работать.
5. **Given** адрес указан с ошибкой или сервер недоступен, **When** проверка, **Then** сообщение «сервер недоступен по этому адресу», без технического мусора.
6. **Given** разработчик сохраняет настройки, **When** браузер запрашивает разрешение на доступ к адресу Gitea, **Then** расширение запрашивает доступ только к этому адресу, а не ко всем сайтам.

### User Story 2 — Быстрый переход к репозиторию (Priority: P1)

Разработчик нажимает горячую клавишу или иконку, начинает печатать часть имени репозитория и за пару нажатий открывает нужный репозиторий, его PR или его сборки в новой вкладке. Часто используемые репозитории он закрепляет, и они всегда стоят сверху.

**Why this priority**: самый частый сценарий — «переключиться между нашими репами»; ценен сам по себе, без PR и сборок.

**Independent Test**: при подключённом Gitea открыть окно, набрать фрагмент имени, клавиатурой выбрать результат и открыть его тремя способами (репозиторий / PR / сборки); закрепить репозиторий и убедиться, что после перезапуска браузера он сверху.

**Acceptance Scenarios**:

1. **Given** окно открыто, **When** оно появилось, **Then** курсор уже стоит в поле поиска.
2. **Given** пустое поле, **Then** показаны закреплённые репозитории, ниже — мои репозитории по времени последнего обновления.
3. **Given** разработчик печатает, **When** пауза в наборе около 0,2 с, **Then** список фильтруется; результат показывает `владелец/имя`, признак приватности и время последнего обновления.
4. **Given** выделен результат, **When** Enter, **Then** репозиторий открывается в новой вкладке; Ctrl/Cmd+Enter — открывается список его PR; Shift+Enter — список его сборок.
5. **Given** список, **When** стрелки вверх/вниз, **Then** выделение перемещается по списку.
6. **Given** репозиторий закреплён, **When** браузер перезапущен или разработчик вошёл в браузер на другом компьютере, **Then** закреплённые репозитории на месте.
7. **Given** адресная строка браузера, **When** разработчик вводит ключевое слово расширения и фрагмент имени, **Then** получает подсказки репозиториев и по выбору переходит в репозиторий.

### User Story 3 — PR, которые ждут меня (Priority: P1)

Разработчик открывает окно и видит, какие PR ждут его ревью, в каком состоянии его собственные PR и (по желанию) остальные открытые PR. На иконке расширения число PR, ожидающих его ревью, — видно, не открывая окна.

**Why this priority**: вторая по частоте боль — «что от меня ждут» и «прошёл ли CI у моего PR».

**Independent Test**: создать в Gitea PR с запросом ревью на разработчика; убедиться, что он появился в группе «Нужно моё ревью», бейдж увеличился на 1, а у PR виден статус CI.

**Acceptance Scenarios**:

1. **Given** есть открытые PR, **Then** они разбиты на группы «Нужно моё ревью», «Мои PR», «Остальные открытые»; последнюю группу можно отключить в настройках.
2. **Given** PR в списке, **Then** видны заголовок, `владелец/репо #номер`, автор, время обновления, статус CI последнего коммита (успех / падение / в процессе / нет проверок), признак черновика и признак конфликта слияния, если Gitea его сообщает.
3. **Given** PR с запущенными проверками, **When** проверки завершились, **Then** статус CI в списке меняется не позже следующего цикла обновления.
4. **Given** клик по PR, **Then** PR открывается в новой вкладке.
5. **Given** режим бейджа «ревью» (по умолчанию), **Then** число на иконке = число PR в группе «Нужно моё ревью»; при нуле бейдж скрыт.

---

### User Story 4 — Мониторинг сборок (Priority: P2)

Разработчик видит, какие сборки идут прямо сейчас (в очереди, ожидают, выполняются) и какие недавно завершились, и сразу переходит к нужному запуску. У выполняющихся сборок длительность тикает в реальном времени.

**Why this priority**: закрывает «мониторить сборки по actions»; зависит от подключения (P1), но не от PR.

**Independent Test**: запустить workflow в Gitea; убедиться, что запуск появился в разделе активных не позже интервала опроса + 5 с, длительность тикает, после завершения запуск переехал в «недавние» с итоговым статусом.

**Acceptance Scenarios**:

1. **Given** есть запуски, **Then** они разделены на группы «Мои и закреплённые» (развёрнута) и «Остальные» (свёрнута, со счётчиком активных и упавших); в каждой группе активные сверху, ниже — завершённые за последние N часов (по умолчанию 24) со статусом успех / падение / отменён / пропущен.
2. **Given** слияние в общую ветку перезапустило проверки десятков чужих PR, **Then** эти запуски попадают в свёрнутую группу «Остальные» и не вытесняют мои.
3. **Given** запуск в списке, **Then** видны репозиторий, название workflow, ветка, событие (push, pull_request, …), автор, статус с иконкой в стиле Gitea и длительность; клик открывает страницу запуска.
4. **Given** Gitea не поддерживает сборки или токену не хватает прав на них, **Then** раздел показывает объяснение, остальные разделы работают как обычно.
5. **Given** активных запусков нет, **Then** раздел показывает «нет активных сборок», а не пустое место.
6. **Given** режим бейджа «сборки» или «сумма», **Then** число на иконке — активные сборки группы «Мои и закреплённые» или сумма «ревью + эти сборки»; чужие перезапуски бейдж не увеличивают.

---

### User Story 5 — Уведомления и красный бейдж (Priority: P2)

Разработчик работает в другой вкладке и получает системное уведомление, когда упала сборка по его PR или его пушу, когда его назначили ревьюером, когда сборка по его PR успешно завершилась. Если за последние N минут упала «его» сборка, бейдж становится красным.

**Why this priority**: даёт реакцию без постоянного открытия окна, но опирается на US3 и US4.

**Independent Test**: включить уведомление «сборка упала», запушить заведомо падающий коммит в свой PR; получить ровно одно уведомление, клик открывает страницу запуска; бейдж красный в течение N минут.

**Acceptance Scenarios**:

1. **Given** включено «сборка упала» с охватом «мои PR / мои пуши / все отслеживаемые», **When** подходящая сборка упала, **Then** ровно одно уведомление; повторные опросы и перезапуск браузера не дают дубликатов.
2. **Given** включено «успешная сборка по моему PR», **When** такая сборка завершилась успехом, **Then** одно уведомление.
3. **Given** включено «меня назначили ревьюером», **When** появился новый PR с запросом моего ревью, **Then** одно уведомление.
4. **Given** клик по уведомлению, **Then** открывается соответствующая страница (запуск, PR).
5. **Given** расширение впервые подключилось к Gitea, **Then** уже существующие падения и запросы ревью не вызывают лавину уведомлений: уведомляется только то, что произошло после подключения.
6. **Given** за последние N минут упала сборка по моему PR или моему пушу, **Then** бейдж красный; иначе нейтральный.
7. **Given** уведомление о новом комментарии или ревью в моём PR включено (этап полировки), **Then** одно уведомление на событие, клик ведёт к комментарию.

---

### User Story 6 — Настройка охвата и частоты (Priority: P3)

Разработчик настраивает, как часто обновлять данные, что показывает бейдж, какие уведомления включены, окно «недавних» сборок и набор отслеживаемых репозиториев (включить, исключить, закрепить).

**Why this priority**: разумные значения по умолчанию работают без этого; настройка — для тонкой подгонки.

**Independent Test**: изменить каждую настройку и проверить, что поведение изменилось без переустановки расширения.

**Acceptance Scenarios**:

1. **Given** интервал опроса, **Then** по умолчанию 60 с, меньше 30 с установить нельзя.
2. **Given** есть мои активные сборки, **Then** данные сборок обновляются чаще базового интервала (адаптивно) и возвращаются к базовому, когда активных нет.
3. **Given** охват «все репозитории моих организаций», **Then** можно исключить репозиторий или организацию и добавить репозиторий вне своих организаций; исключённые не появляются ни в сборках, ни в «Остальных открытых» PR.
4. **Given** Gitea не отдаёт сборки организации целиком, **Then** настройки показывают, что включён опрос по репозиториям с лимитом 30, и предупреждают при превышении.

### Edge Cases

- Токен отозван или истёк во время работы: все разделы показывают «токен недействителен — открыть настройки», фоновый опрос не долбит сервер повторными ошибками.
- Gitea недоступен (сеть, VPN, перезапуск сервера): окно показывает последние известные данные с отметкой «данные на ЧЧ:ММ, нет связи», а не пустые разделы.
- Токену не хватает одного права (например, на уведомления): страдает только соответствующая функция, диагностика называет недостающее право.
- Workflow без имени, запуск без ветки (ручной запуск, расписание), запуск по тегу: элемент списка всё равно читаем.
- Перезапуск упавшей сборки: новая попытка, упавшая снова, даёт новое уведомление; упавшая и тут же перезапущенная не даёт повторного уведомления за ту же попытку.
- PR из форка, PR без проверок, PR-черновик: статус CI «нет проверок», признак черновика.
- Очень много открытых PR или репозиториев: окно остаётся отзывчивым, списки прокручиваются внутри раздела.
- Окно открыто долго: длительность тикает, данные обновляются, нет утечек и зависаний.
- Браузер был закрыт несколько часов: при старте не должно прийти уведомлений о событиях, которые давно устарели (старше окна «недавних»).
- Смена адреса Gitea или токена: кэш и история показанных уведомлений прежнего подключения не смешиваются с новыми.

## Requirements *(mandatory)*

### Functional Requirements

**Подключение и безопасность**

- **FR-001**: Расширение MUST позволять указать адрес Gitea и личный токен доступа и проверить подключение с диагностикой: неверный адрес / сервер недоступен, токен недействителен, недостаточно прав (с названием недостающего права), сборки недоступны на этой версии Gitea.
- **FR-002**: Расширение MUST показывать ссылку на страницу создания токена в Gitea и список минимальных прав токена (только чтение: репозитории, задачи и PR, пользователь, уведомления, организации).
- **FR-003**: Токен MUST храниться только локально на этом устройстве, никогда не синхронизироваться между устройствами, не попадать в журналы и сообщения об ошибках.
- **FR-004**: Расширение MUST запрашивать у браузера доступ только к адресу указанного Gitea, в момент сохранения настроек; доступ «ко всем сайтам» запрещён.
- **FR-005**: Расширение MUST только читать данные Gitea; никаких изменяющих действий (слияние, перезапуск, комментарии) в этой версии.
- **FR-006**: Расширение MUST работать без собственного сервера, аналитики и загрузки кода со сторонних адресов; весь трафик идёт только в указанный Gitea.
- **FR-007**: Модель данных MUST допускать несколько подключений к разным Gitea в будущем; интерфейс в этой версии поддерживает одно.

**Репозитории**

- **FR-010**: Окно MUST открываться с фокусом в поле поиска репозиториев и фильтровать список по мере ввода (задержка около 0,2 с).
- **FR-011**: При пустом запросе MUST показываться закреплённые репозитории, затем репозитории разработчика по времени обновления.
- **FR-012**: Элемент списка MUST показывать `владелец/имя`, признак приватности, время последнего обновления.
- **FR-013**: Навигация MUST работать с клавиатуры: стрелки, Enter (репозиторий), Ctrl/Cmd+Enter (PR репозитория), Shift+Enter (сборки репозитория); клик — как Enter.
- **FR-014**: Разработчик MUST иметь возможность закрепить и открепить репозиторий; закреплённые синхронизируются между устройствами разработчика.
- **FR-015**: Переход к репозиторию MUST быть доступен из адресной строки по ключевому слову (подсказки по мере ввода).

**Pull Requests**

- **FR-020**: Раздел PR MUST показывать группы «Нужно моё ревью», «Мои PR», «Остальные открытые»; последняя отключается в настройках.
- **FR-021**: Элемент PR MUST показывать заголовок, `владелец/репо #номер`, автора, время обновления, статус CI последнего коммита (успех / падение / в процессе / предупреждение / нет проверок), признак черновика, признак конфликта слияния.
- **FR-022**: Статус CI MUST запрашиваться только для показываемых PR и переиспользоваться, пока последний коммит PR не изменился и статус окончательный.
- **FR-023**: Клик по PR MUST открывать его в новой вкладке.

**Сборки**

- **FR-030**: Раздел сборок MUST делить запуски на две группы: «Мои и закреплённые» (мой пуш, мой PR, закреплённый репозиторий) — развёрнута; «Остальные» — свёрнута, в заголовке счётчик активных и упавших. Внутри каждой группы активные запуски (в очереди, ожидают, выполняются) сверху, ниже — завершённые за последние N часов (по умолчанию 24). Состояние свёрнутости запоминается.
- **FR-031**: Элемент запуска MUST показывать репозиторий, название workflow, ветку, событие, автора, статус с иконкой, длительность (у выполняющихся — тикает в реальном времени), ссылку на запуск.
- **FR-032**: Названия и иконки статусов MUST совпадать с интерфейсом Gitea: waiting, blocked, running, success, failure, cancelled, skipped.
- **FR-033**: Если сборки недоступны (версия Gitea, права токена), раздел MUST показывать объяснение, а остальные разделы — работать.
- **FR-034**: Охват по умолчанию («наши репы») для раздела сборок и группы «Остальные открытые» PR — все репозитории всех организаций, в которых состоит разработчик, плюс его собственные репозитории; закреплённые показываются первыми. Если Gitea не отдаёт сборки организации целиком (права, версия), расширение переходит на опрос по репозиториям с лимитом 30: закреплённые + где были мои PR или сборки за 7 дней, и сообщает об этом в диагностике.
- **FR-035**: Разработчик MUST иметь возможность исключить репозитории или целые организации из охвата и явно добавить репозитории вне своих организаций; в режиме опроса по репозиториям при превышении лимита — предупреждение о нагрузке.

**Фоновое обновление**

- **FR-040**: Данные MUST обновляться в фоне с настраиваемым интервалом: по умолчанию 60 с, минимум 30 с.
- **FR-041**: При наличии активных сборок группы «Мои и закреплённые» обновление сборок MUST учащаться (адаптивно) и возвращаться к базовому интервалу, когда активных нет. Фоновое обновление не может быть чаще 30 с (ограничение браузера); при открытом окне расширения сборки обновляются раз в 15–20 с.
- **FR-042**: Окно MUST сразу показывать последние сохранённые данные и подтягивать свежие после открытия; у устаревших данных видно время последнего обновления.
- **FR-043**: Расширение MUST ограничивать число одновременных запросов к Gitea (не больше 4) и переиспользовать неизменившиеся данные, чтобы не перегружать сервер.
- **FR-044**: При ошибках авторизации фоновое обновление MUST приостанавливаться до исправления настроек; при недоступности сервера — повторять с увеличивающейся паузой.

**Бейдж**

- **FR-050**: Бейдж MUST показывать число в выбранном режиме: PR на моё ревью (по умолчанию), активные сборки группы «Мои и закреплённые», сумма этих двух чисел; при нуле — скрыт.
- **FR-051**: Бейдж MUST быть красным, если за последние N минут (по умолчанию 30) упала сборка по моему PR или моему пушу; иначе нейтральным.

**Уведомления**

- **FR-060**: Разработчик MUST иметь возможность по отдельности включать уведомления: сборка упала (охват: мои PR / мои пуши / все отслеживаемые), сборка по моему PR успешна, меня назначили ревьюером, новый комментарий или ревью в моём PR.
- **FR-061**: Одно событие MUST давать не больше одного уведомления, в том числе после перезапуска браузера; попытка перезапуска сборки считается отдельным событием.
- **FR-062**: При первом подключении и после долгого отсутствия связи расширение MUST НЕ уведомлять о событиях, случившихся до подключения или старше окна «недавних».
- **FR-063**: Клик по уведомлению MUST открывать соответствующую страницу (запуск, PR, комментарий).

**Интерфейс**

- **FR-070**: Окно MUST иметь три раздела (Репо, PR, Сборки) и открываться на последнем использованном.
- **FR-071**: Интерфейс MUST поддерживать светлую и тёмную тему по системной настройке.
- **FR-072**: Каждый раздел MUST иметь понятные пустые состояния и состояния ошибок со ссылкой на настройки, где уместно.
- **FR-073**: Язык интерфейса — всегда русский, независимо от языка браузера (английская локаль не поставляется); строки по-прежнему вынесены в `_locales`.
- **FR-076**: Окно и страница настроек MUST выглядеть как стандартный интерфейс shadcn/ui (канонические компоненты и токены без кастомизации): карточки секций, подписи над полями, выпадающие списки и переключатели shadcn, вкладки, бейджи статусов, уведомление-тост о сохранении и об ошибке; тёмная тема по системной настройке.
- **FR-074**: Окно MUST открываться горячей клавишей (по умолчанию Alt+G, переназначается средствами браузера).
- **FR-075**: Каждая версия расширения MUST выпускаться архивом с номером версии в релизах репозитория расширения в нашем Gitea (сборка по тегу); README MUST описывать установку «загрузить распакованное» и ручное обновление. Номер версии виден на странице настроек.

### Key Entities

- **Подключение**: адрес Gitea, токен (только локально), учётная запись разработчика, версия Gitea, доступность сборок и уведомлений, результат последней проверки.
- **Репозиторий**: владелец, имя, приватность, время обновления, признаки «закреплён», «отслеживается», «исключён».
- **Pull Request**: репозиторий, номер, заголовок, автор, время обновления, черновик, конфликт, последний коммит, статус CI, группа (моё ревью / мой / прочий).
- **Запуск сборки**: репозиторий, workflow, ветка, событие, автор, попытка, статус, время начала и завершения, ссылка.
- **Событие уведомления**: вид (падение, успех, ревью, комментарий), ключ уникальности (например, запуск + попытка), время, ссылка; история показанных хранится ограниченно.
- **Настройки**: интервал, режим бейджа, окно «недавних», окно «красного бейджа», включённые уведомления и охват, списки включённых/исключённых/закреплённых репозиториев, видимость группы «Остальные открытые», последний раздел окна.
- **Снимок данных**: последние полученные PR, запуски и время обновления — для мгновенного показа окна.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После ввода адреса и токена разработчик видит свои репозитории, PR и активные сборки не позже чем через 5 с.
- **SC-002**: Окно показывает сохранённые данные менее чем за 0,1 с после открытия.
- **SC-003**: Разработчик открывает нужный репозиторий из любой вкладки не более чем за 3 с и 5 нажатий клавиш (горячая клавиша, 2–3 символа, Enter).
- **SC-004**: Запуск workflow появляется в разделе сборок не позже интервала опроса + 5 с.
- **SC-005**: Падение сборки по PR разработчика даёт ровно одно системное уведомление в 100% проверочных случаев (включая перезапуск браузера); клик открывает страницу запуска.
- **SC-006**: При неверном токене или недоступном Gitea расширение ни разу не показывает пустой или сломанный экран; каждое такое состояние имеет понятное сообщение.
- **SC-007**: Токен не обнаруживается ни в синхронизируемом хранилище, ни в журналах, ни в сообщениях об ошибках (проверка просмотром всех трёх).
- **SC-008**: При недоступности сборок разделы «Репо» и «PR» полностью работают.
- **SC-009**: Фоновая нагрузка на Gitea при базовом интервале не превышает 20 запросов в минуту на одного разработчика при опросе по одной организации, 40 — по трём, и 45 — в запасном режиме по репозиториям (30 репозиториев); оценка описана в README.
- **SC-010**: Размер окна расширения, загружаемого при открытии, не превышает 400 КБ (было 300 КБ «ориентиром» ТЗ; поднято 2026-09-28 после перехода на React + shadcn по решению владельца — React DOM ≈ 220 КБ; расширение грузится с диска).

## Assumptions

- Gitea один — `git.sadmin.app`, версия 1.27.3; адрес по умолчанию подставляется в настройки, но редактируется. Поддержка сборок на более старых версиях проверяется при подключении; минимальная версия фиксируется на этапе плана.
- Пользователи — разработчики команды SimplX (сначала владелец); магазин расширений не используется.
- Браузер — Chrome последних версий (и совместимые на том же движке); мобильные браузеры и Firefox вне охвата.
- «Мой пуш» — запуск, где автор или инициатор — учётная запись разработчика; «мой PR» — PR, созданный разработчиком.
- Конфликт слияния показывается, только если Gitea сообщает его в данных списка PR; отдельных тяжёлых проверок ради него не делается.
- Название workflow берётся из того, что сообщает Gitea (имя файла workflow, если отдельного имени нет).
- Отмена, перезапуск, слияние и другие изменяющие действия — вне охвата этой версии.
- Уведомления о комментариях и ревью (этап полировки) опираются на встроенные уведомления Gitea пользователя и работают только при соответствующем праве токена.
- Порядок поставки по приоритетам: P1 (подключение, репозитории с адресной строкой, PR со статусом CI, бейдж) → P2 (сборки, фоновое обновление, уведомления) → P3 (охват и тонкая настройка, комментарии).
- «Остальные открытые» PR показываются первыми 50 на организацию; остальное — ссылкой «ещё N» в Gitea.
